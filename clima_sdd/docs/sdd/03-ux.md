# SDD-003 — Frontend, UX y accesibilidad

## Metadata

| Campo | Valor |
|---|---|
| Version | 2.0 |
| Estado | Implementado |
| Tecnologia | HTML server-side y CSS |
| Directorios | `frontend/templates`, `frontend/static` |

## Principios de interfaz

La interfaz debe ser clara, mobile-first, coherente entre clima y turismo, y no depender de JavaScript para los flujos principales.

## Requisitos funcionales

- RF-UX-01: mostrar navegacion entre clima, turismo y sesion.
- RF-UX-02: cada input debe tener etiqueta visible.
- RF-UX-03: mostrar errores cerca del contexto y con `role="alert"`.
- RF-UX-04: mantener el valor de ciudad despues de validar.
- RF-UX-05: presentar metricas meteorologicas con estructura semantica.
- RF-UX-06: diferenciar visualmente datos observados y predicciones.
- RF-UX-07: no mostrar contraseñas ni hashes en respuestas HTML.

## Accesibilidad

- Navegacion completa con teclado.
- Orden de foco logico.
- Contraste legible y estados de foco visibles.
- No usar color como unica señal de error.
- Titulos jerarquicos y `lang="es"`.
- Mensajes de error anunciables por lector de pantalla.

## Responsive

En pantallas menores a 680 px, los formularios y tarjetas se apilan. No debe existir scroll horizontal ni botones fuera del viewport.

## Criterios de aceptacion

1. Login, registro, clima y turismo se pueden usar sin JavaScript.
2. En móvil se leen todas las metricas sin zoom horizontal.
3. Una prediccion muestra confianza, base, version y disclaimer.
4. Los templates solo presentan datos; no contienen consultas SQL ni llamadas HTTP.

## Pruebas

Unitarias de rutas en `tests/`; revisión manual en Chrome, Edge y Firefox; futura prueba E2E con Playwright y auditoría automatizada de accesibilidad.

## Pendientes

Estados de carga, diseño de componentes, iconos meteorológicos accesibles, paginación del catálogo y soporte futuro para frontend SPA.
